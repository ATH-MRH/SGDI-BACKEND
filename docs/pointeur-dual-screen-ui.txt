INTERFACE
- Header compact et fixe : logo, date et horloge existante, Société, Site,
  scanner, utilisateur, plein écran et déconnexion.
- Bandeau Vacation supprimé. Les informations de maintien nécessaires aux
  décisions de pointage restent disponibles dans le contexte métier existant.
- Deux blocs indépendants, ratio 2:1 ; débordements gérés à l'intérieur des blocs.
- Trois modes existants : QR, facial, manuel. Recherche intégrée sous les modes.
- Fiche employé compacte, photo/initiales et quatre informations sans répétitions.
- Barre horizontale verte / rouge / orange. Aucun raccourci F1/F2/F3 : ces touches
  peuvent être réservées au navigateur ou au poste terminal.
- Cinq compteurs canoniques compacts ; liste des présents avec scroll interne.
- Lien Voir tous les présents : affiche les présents canoniques, y compris une
  vacation commencée la veille, dans le tableau inférieur.
- Aujourd'hui : une situation par employé/jour, première entrée et dernière sortie.
  La synthèse est calculée sur le journal avant de limiter les mouvements retournés.
- Entrées, Sorties (durée et type de sortie persistés) et Anomalies existantes.
- Actions de saisie manuelle requise conservées sur le poste principal.

SOCIÉTÉ / SITE / RBAC
Le catalogue vient de /api/portal/attendance-sites, enrichi du libellé société.
Aucune société, aucun site ni utilisateur opérationnel n'est codé en dur.
Le choix Toutes les sociétés recouvre seulement le périmètre autorisé.
Le filtre société est transmis aux lectures ; sites et société sont intersectés
sur le serveur. Une société injectée non autorisée renvoie 403.
La recherche filtre avant LIMIT 8, et ne renvoie pas l'affectation d'un site interdit.
Les écritures QR / manuelles transmettent le filtre société ; le serveur contrôle
la société de l'employé et l'affectation canonique utilisée par Attendance Core.
Un périmètre société vide d'un compte restreint n'est pas un accès global.
Les administrateurs à accès global explicite conservent leur comportement existant.
Les fixtures historiques de lecteurs restreints sont mises en conformité avec
l'exigence société ET site explicites ; aucune permission production n'est modifiée.
Le correctif module + permission fine ABANDON conserve ses tests de non-régression.

FENÊTRE DÉTACHÉE
Route : /pointeur/suivi. Même application et même session, présentation de suivi seule.
Fenêtre navigateur nominative : atlas-pointeur-suivi. Un deuxième clic la rappelle ;
après fermeture, un clic la rouvre. Le tableau principal reste disponible.
Filtres Société, Site, Date et Recherche ; Actualiser et plein écran volontaire.
Aucune caméra ni scanner démarré par la vue détachée.
Les colonnes supplémentaires utilisent les mêmes données autorisées du serveur.
Le navigateur peut ouvrir la fenêtre en onglet selon ses préférences. La disposition
physique sur le deuxième moniteur est une action de l'utilisateur.

TEMPS RÉEL / PERFORMANCE
Le mécanisme existant attendance-live est réutilisé : 2 s sur le poste principal,
5 s sur la fenêtre de suivi ; historique périodique à 15 s et rafraîchissement
lors d'un nouveau mouvement. Aucun WebSocket, SSE ou système de diffusion parallèle.
Le changement de Société/Site est partagé via le storage natif du navigateur.
Les données métier sont toujours relues depuis le serveur dans chaque fenêtre.
Les réponses correspondant à un ancien filtre ne remplacent pas la sélection courante.
Le rendu du tableau utilise setHTML : aucune réécriture si le contenu est inchangé.
Limites explicites : 200 mouvements, 200 situations journalières, 200 anomalies.
Les compteurs portent sur le périmètre complet, pas sur les seules lignes affichées.
La vue multi-sites réutilise control_post par site pour garder les KPI canoniques.
