## Endpoints (backend drh existant — app/modules/drh/routes.py)
- GET /api/drh/candidates/page?society&status&q&page&page_size → CandidatePage {items, total, page, page_size, pages}
- GET /api/drh/candidates?society&status → list[CandidateOut]
- POST /api/drh/candidates (write H2) → CandidateCreate {first_name,last_name,phone,email,desired_position,society,expected_salary,recruiter_opinion,status,data{}}
- PUT /api/drh/candidates/{id} (write H2) → CandidateUpdate (partiel)
- POST /api/drh/candidates/validate-section?section=&candidate_id= (validate H3) → validation d'une section (dont section fantôme 'mensurations')
- POST /api/drh/candidates/{id}/validate-final (validate H3) → fiche de position validée → réserve
- POST /api/drh/candidates/{id}/marquer-contractualisation (validate H3) → statut a_contractualiser
- POST /api/drh/candidates/{id}/recruit (validate H3) → crée l'employé
- DELETE /api/drh/candidates/{id} (delete H4 ; cross-société = admin-system)
- GET /api/irongs/positions → postes (select posteSouhaite, section 3)
- Modèle Candidate = colonnes {first_name,last_name,phone,email,desired_position,society,expected_salary,recruiter_opinion,status} + **data JSON** (toutes les autres données des 7 sections : nin, dateNaissance, avisDecision, wilaya, photo, cv, habilitations, langues, experience[], verif*, flags de validation de section, archive…). Mapping candidateFromApi: backendId=id, nom←last_name, prenom←first_name, telephone←phone, posteSouhaite←desired_position, societe←society, salairePrevu←expected_salary, statut←status, recruiter_opinion=avisCommentaire.
